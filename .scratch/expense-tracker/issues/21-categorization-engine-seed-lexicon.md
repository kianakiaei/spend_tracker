## Question

موتور خالص TypeScript بدون وابستگی ML، عین تحقیق ۰۱ + محتوای تثبیت‌شدهٔ تیکت ۱۳:

- `src/lib/categorization/seed-lexicon.ts` **عین محتوای کامنت تیکت ۱۳** (۷۴ کلید کانونی: ۶۸ توکنی + ۶ عبارتی در `SYSTEM_CATEGORIES` + `SEED_LEXICON`) — فقط داده؛ ناوردای «هر کلید کانونی است» تست می‌شود.
- نرمال‌ساز فارسی (~۲۰ خط تحقیق ۰۱): unify ي/ی و ك/ک، NFKC، حذف اعراب/تنوین/کشیده/علائم RTL، یکسان‌سازی ارقام فارسی/عربی به لاتین، ZWNJ = فاصله، فشرده‌سازی فاصله‌ها.
- دو Map درون‌حافظه‌ای (عبارتی/توکنی): فلت‌کردن `tokens` → Map توکنی و `phrases` → Map عبارتی؛ **عبارت‌ها به توکن‌های سازنده تجزیه نمی‌شوند** (دلیل جدا بودن فیلدها — تیکت ۱۳).
- نردبان شش‌پله‌ای: learned phrase > learned token > lexicon phrase > lexicon token > prefix > fuzzy (Levenshtein Δ1، توکن ≥۴ حرف) > null — «عبارت قبل از توکن» بار معنایی دارد («اسنپ فود» باید از «اسنپ» جلو بزند).
- جست‌وجوی عبارت: کل عنوان کانونی + بگرام‌های مجاورِ توکن‌های معنادار («اسنپ فود شام» → بگرام «اسنپ فود»).
- confidence = purity × support شمارنده‌ها — فقط گزارشی در پاسخ، نه گِیت تصمیم (تصمیم «همیشه پیشنهاد» تیکت ۰۶).
- استخراج کلید برای یادگیری: عبارت + توکن‌های بارز بدون stopword («خرید نان»/«نان خریدم» هر دو «نان») + تابع خالص learn (count++) و decay (×۰٫۵ در تناقض) روی شمارنده‌ها — نوشتن SQL با تیکت ۲۲ است.
- موتور کاملاً خالص و تزریقی: ورودی = واژه‌نامهٔ سیستمی + learnedKeys کاربر + فهرست دسته‌های او (id/name/slug)؛ **حل slug → UUID بیرون موتور** انجام می‌شود؛ خروجی حدس = `{categoryId | null, source: 'learned'|'system', matchedKey, confidence}`.

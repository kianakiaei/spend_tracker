# 27 — جریان ثبت/ویرایش خرج: شیت پایینی + پیشنهاد زنده

Type: task
Status: open
Blocked by: 25, 26

## Question

فرم ثبت و شیت ویرایش، طبق ترکیب تأییدشدهٔ ۰۷ و رفتار «همیشه پیشنهاد» ۰۶. **الزام: frontend-design**:

- **شیت ثبت پایینی** (دکمهٔ + اکسنت یشمی): عنوان؛ مبلغ با **نمایش زندهٔ fa-IR**؛ گام‌روز جلالی با `react-multi-date-picker` (`calendar={persian}` + `locale={persian_fa}`، state میلادی — تحقیق ۰۴)؛ **ماه هدف صریح**: «ثبت در مرداد ۱۴۰۵» (چون فرم می‌تواند از داشبورد ماه دیگر باز شود)؛ پیش‌فرض تاریخ: در ماه جاری = امروز؛ در ماه دیگر = **«بدون تاریخ»** (خرجِ بی‌تاریخ عضو ماه فرم — تصمیم ۱۵)؛ تاریخ‌دار همیشه به ماه خودش می‌رود حتی اگر با ماه فرم فرق کند.
- **چیپ دسته با بج «پیشنهاد»:** پیشنهاد زندهٔ سمت کلاینت با سرویس مشترک ۲۲ (واژه‌نامه + learnedKeys + دسته‌ها موقع لود در حافظه؛ پاسخ در میکروثانیه) — با تایپ عنوان به‌روزرسانی با **debounce ~۱۵۰ms**؛ تا وقتی کاربر دست به دسته نزده؛ **بعد از انتخاب دستی، موتور تا پایان همان فرم ساکت** و بج می‌افتد؛ fallback = پربسامدترین (خروجی classify سرویس)؛ بی‌تاریخچه = خوراکی. بی‌اثر بودن فرم هنگام تایپ (هیچ POSTی).
- **شیت ویرایش** (کلیک روی سطر خرج/از دریل‌داون): تغییر آزاد عنوان/مبلغ/تاریخ/دسته؛ دادن تاریخ به بی‌تاریخ → انتقال به ماه همان تاریخ (تصمیم ۱۵)؛ حذف با تأیید.
- ثبت/ویرایش/حذف از **fetch wrapper تایپ‌شدهٔ ۲۵** به `/api/v1/expenses` — نه Server Action مستقیم (قرارداد تیکت ۱۲: منطقِ فقط-اکشن در سرویس است).
- دست‌زدگی/خطای شبکه: پیام عمومی، حفظ دادهٔ فرم.

## Test plan

- component (jsdom + RTL): debounce پیشنهاد و سکوت بعد از تغییر دستی، افتادن بج، نمایش زندهٔ مبلغ fa-IR، چیپ «بدون تاریخ» و پیش‌فرض تاریخ per-ماه، نمایش ماه هدف؛ خوشی‌ها با E2E در ۳۰.

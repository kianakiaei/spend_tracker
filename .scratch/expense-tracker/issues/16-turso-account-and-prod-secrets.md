## Question

کارِ اجرایی که راهش باید زود باز شود — چون نتیجه‌اش می‌تواند انتخاب دیتابیس را هم عوض کند (HITL؛ اکانت و مرورگر با کاربر است):

1. **تست دسترسی از ایران — اول از همه:** ثبت‌نام در Turso از ایران امتحان شود؛ اگر ممکن نشد، تعویض سرویس تصمیم محصولی کاربر است (جانشین ساده: فایل libSQL روی هاست اپ — طبق تحقیق «راه‌اندازی Turso + Drizzle»، §۲.۵).
2. **ریجن:** با `turso db locations --show-latencies` کم‌ترین latency از محل کاربر انتخاب شود (انتظار: اروپا/شرق مدیترانه).
3. **دیتابیس و توکن‌ها:** ساخت دیتابیس prod + دو توکن — database token با `--expiration never` برای اپ و یک read-only برای کوئری‌های ad-hoc. هر دو فقط یک‌بار نمایش داده می‌شوند → مستقیم به password manager/`.env`؛ **هیچ مقدار سکرتی در tracker نوشته نمی‌شود**.
4. **env vars روی Vercel** (با اولین دیپلوی کامل می‌شود): `TURSO_DATABASE_URL`، `TURSO_AUTH_TOKEN`، `APP_URL`، سکرت‌های better-auth، `RESEND_API_KEY`.
5. **آشنایی با بکاپ:** یک `turso db export` اولیه گرفته شود (پلن Free فقط ۱ روز PITR دارد).
6. **Resend (از تیکت ۰۸):** ثبت‌نام Resend + تأیید دامنهٔ کاربر (رکوردهای SPF/DKIM طبق راهنمای خودش) + انتخاب آدرس فرستنده (مثل `no-reply@<دامنه>`) + ساخت API key — برای ریست رمز ایمیلی. تست تحویل به inbox (نه spam) با اولین ریست واقعی.

خروجی: چک‌لیست دقیق مرحله‌به‌مرحله برای کاربر (مثلاً با مهارت wizard)؛ در Answer، نتایج واقعی بدون مقادیر سکرت ثبت شود (ریجن منتخب، URL دیتابیس، تاریخ بکاپ).

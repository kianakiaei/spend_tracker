# 05 — مدل داده و قرارداد سینک

Type: grilling
Status: resolved
Blocked by: 01, 02, 03

## Question

اسکیمای نهایی خرج/دسته/واژه‌نامهٔ یادگرفته و قرارداد سینک چیست؟ (Zod در packages/shared؛ Drizzle سمت سرور؛ Dexie سمت کلاینت)

- Expense: id (UUID)، مبلغ، عنوان، یادداشت اختیاری، categoryId، تاریخ (میلادی)، createdAt/updatedAt، پرچم‌های سینک.
- Category: سیستمی (۶ دستهٔ پایه) در برابر سفارشی؛ نام، آیکن/رنگ؛ قواعد حذف دستهٔ دارای خرج.
- LearnedKeyword: نگاشت کلیدواژه→دسته، منبع (سیستمی/یادگرفته)، وزن/زمان — سینک می‌شود یا لوکال می‌ماند؟
- قرارداد سینک: push/pull دسته‌ای، LWW با updatedAt، رفتار تعارض حذف/ویرایش هم‌زمان، همگام‌سازی اولیه.
- خروجی: تصمیم ثبت‌شده در همین تیکت + ساخت `CONTEXT.md` (واژه‌نامهٔ دامنه) طبق domain-modeling.

## Answer

تصمیم‌های کاربر (گریلینگ، 2026-09-06): مبلغ = **عدد صحیح تومان**؛ **منع حذف دستهٔ دارای خرج**؛ **تکرار خودکار در MVP** به‌شکل الگوی تکرار با تولیدِ خودکارِ قابل ویرایش؛ روزِ بی‌ماه **چسبان به آخرین روز ماه**.

**موجودیت‌های سینک‌شونده (Zod در packages/shared، Drizzle سمت سرور، Dexie سمت کلاینت):**
- `categories`: id (UUIDv7)، name (یکتا برای هر کاربر)، icon، color، kind (`'system' | 'custom'`)، order + ستون‌های سینک (userId، createdAt، updatedAt، deletedAt). شش دستهٔ سیستمی هنگام ثبت‌نام seed می‌شوند؛ سیستمی حذف‌نشدنی (تغییر نام آزاد).
- `expenses`: id، amountToman (int > 0)، title، note?، categoryId (**NOT NULL** — نتیجهٔ مستقیم منع حذف دستهٔ پُر؛ گروه «بدون دسته» وجود ندارد)، occurredAt (رشتهٔ date-only میلادی `'YYYY-MM-DD'` محلی — تحقیق ۰۴)، monthKey (`'1405-06'`، مشتق روی نوشتن از occurredAt برای ایندکس/گروه‌بندی؛ منبع حقیقت همان occurredAt)، sourceRecurringId? + ستون‌های سینک.
- `recurringTemplates`: id، title، amountToman، categoryId، dayOfMonth (۱..۳۱ جلالی)، startDate (date-only)، endDate?، active + ستون‌های سینک. تولید: در بوت/باز شدن ماهِ جاری برای هر الگوی فعالِ واجد شرط، یک خرج با (sourceRecurringId، monthKey) — idempotent با یونیک‌ایندکس `(userId, sourceRecurringId, monthKey)` سمت سرور و کلاینت؛ اگر dayOfMonth در آن ماه نبود → آخرین روزِ همان ماه؛ خرجِ تولیدشده آزادانه ویرایش/حذف می‌شود و به الگو ربطی ندارد.
- `learnedKeys`: key (نرمال‌شده)، categoryId، count، source (`'system' | 'learned'`)، updatedAt + ستون‌های سینک — **سینک می‌شود** (یادگیری بین دستگاه‌ها همراه کاربر می‌رود؛ تحقیق ۰۱).
- فقط-محلی (Dexie، سینک نمی‌شوند): `outboxOps` (opId = UUIDv7 به‌عنوان idempotency key)، `appState` (پروفایل مینیمال + cursor آخرین سینک — تحقیق ۰۲).

**قرارداد سینک** (بر پایهٔ تحقیق‌های ۰۲ و ۰۳): یک endpoint دسته‌ای `POST /api/sync` (push + pull در یک رفت‌وبرگشت). Push آرایه‌ای از opها `{opId, entity, id, payload | tombstone}`؛ pull تغییرات پس از cursor مونوتونیک سمت سرور، صفحه‌بندی‌شده. تعارض: LWW با updatedAt سمت سرور + upsert شرطی؛ حذف = tombstone که اگر updatedAtاش تازه‌تر باشد می‌برد. opId تکراری = no-op. سینک اولیه: pull کامل صفحه‌بندی‌شده پس از ورود. 401 در حین سینک → خروج محلی.

**UX حذف دسته (منع حذف پُر):** دکمهٔ حذف برای دستهٔ دارای خرج غیرفعال با نشانِ تعداد خرج‌ها، به‌همراه پیشنهاد «انتقال همهٔ خرج‌ها به دستهٔ دیگر» به‌عنوان راه میان‌بر.

**واژه‌نامه:** [CONTEXT.md](../../../CONTEXT.md) ساخته شد (خرج، دسته، دستهٔ سیستمی/سفارشی، الگوی تکرار، ماهِ وقوع، واژهٔ یادگرفته، واژه‌نامهٔ سیستمی).

**پیامد روی fog:** «جزئیات CRUD» حل شد (ویرایش/حذف خرج آزاد و tombstone؛ حذف دسته = منع پُر + انتقال گروهی)؛ «ناوبری بین ماه‌ها» حل شد (ناوبری به هر ماه جلالی، ناوگان تولید الگو فقط در ماه جاری)؛ فقط «پیش‌نمایش اقساط ماه‌های آینده» در fog ماند.

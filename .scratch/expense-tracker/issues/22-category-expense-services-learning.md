## Question

سرویس‌های دامنه در `src/lib/services` — قاعدهٔ تست‌پذیری تیکت ۱۲: **هیچ import از `next/*`**؛ db و ورودی‌ها تزریقی؛ خطاهای دامنه به‌شکل نوع‌دار (handler تیکت ۲۵ آن‌ها را به 409/400 ترجمه می‌کند):

- `categoryService`: CRUD؛ **منع حذف دستهٔ دارای خرج** (خطای دامنه → 409 در handler؛ چون FK خاموش است این فقط اینجاست)؛ **سیستمی حذف‌نشدنی** (تغییر نام آزاد)؛ `moveExpenses(categoryId, targetCategoryId)` برای انتقال گروهی؛ یکتایی نام per user؛ ترتیب.
- `expenseService`: create/update/delete آزاد و بدون هیچ قید تاریخی (گذشته/آینده/بی‌تاریخ مجاز — تصمیم ۱۵)؛ قاعدهٔ monthKey روی نوشتن: تاریخ‌دار = مشتق با `jalaliMonthKey`؛ **بی‌تاریخ = ماه فرم (پارامتر صریح سرویس)**؛ ویرایشِ دادنِ تاریخ به بی‌تاریخ = انتقال به ماه همان تاریخ.
- **یادگیری روی هر ذخیره** (ایجاد/ویرایش) با دستهٔ نهایی X طبق تیکت ۰۶: استخراج کلیدهای نرمال‌شدهٔ عنوان (موتور ۲۱) → upsert روی `learnedKeys`؛ **تناقض با پیشنهادِ موتور → decay نرم ×۰٫۵ دستهٔ پیشنهادی + count دستهٔ جدید**؛ حذف خرج یادگیری را برنمی‌گرداند.
- `classify(userId, title)`: موتور با learnedKeys+lexicon+دسته‌های کاربر (حل slug→UUID همین‌جا)؛ **fallback = پربسامدترین دستهٔ خود کاربر** (شمار خرج‌ها)؛ برای کاربرِ بی‌تاریخچه = دستهٔ سیستمی اول (خوراکی)؛ خروجی با source/matchedKey/confidence. همین سرویس مشترک، منبع پیشنهادِ زندهٔ کلاینت (تیکت ۲۷) و endpoint بی‌اثر (تیکت ۲۵) است.
- فهرست خرج‌های ماه `listByMonth(userId, monthKey)`: مرتب‌سازی نمایش (بی‌تاریخ‌ها بالای لیست با چیپ «بدون تاریخ» — تصمیم ۱۵؛ بعد تاریخ)، برگرداندن دستهٔ هر خرج.
